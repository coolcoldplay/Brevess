# R26：接入本机 DeepSeek Harness

本轮新增的 Harness 连接复用官方桌面应用保存的登录，**无需填写 API Key 或服务网址**。目前验证并支持的官方 Harness 版本是 **0.2.0-rc.2**。

“本机”指通过本机 Harness 客户端接入官方账号服务；模型推理仍使用该账号的官方服务。使用它分析论文时，相应文本和图片会随模型请求发送。

## 1. 手动更新两个组件

本次验收包位于 `dist/Brevess-v1.0.1-reliability-20261001-acceptance-r26.1/`，提供：

| 文件 | 用途 |
| --- | --- |
| `Brevess-v1.0.1-reliability-20261001-acceptance-r26.1-browser.zip` | 浏览器扩展 |
| `Brevess-v1.0.1-reliability-20261001-acceptance-r26.1-Windows-companion.zip` | Windows 本机配套，包含新增 Harness 桥 |
| `Brevess-v1.0.1-reliability-20261001-acceptance-r26.1-full.zip` | 两者合并的完整包 |

**已有旧版扩展和配套也需要分别更新。只更新浏览器扩展，旧配套可能无法响应 Harness 请求。** 本次交付不自动安装、注册或覆盖你当前使用的版本。

1. 完整解压浏览器包。在 `edge://extensions/` 或 `chrome://extensions/` 打开开发者模式，加载解压后直接包含 `manifest.json` 的目录。交付目录中已解压的同一组件名为 `browser-extension`。已有加载版本按当前浏览器的扩展更新方式切换到新目录。
2. 完整解压 Windows 配套包，双击其中的 `Install-Brevess-Codex-Bridge.cmd`。完整包中的对应文件位于 `native-host`。这个安装器沿用原名称，安装的共享配套已包含 Harness 支持。
3. 安装完成后重新启动浏览器，或重新加载扩展，再刷新正在阅读的论文页面。

如果安装器提示扩展 ID 不在允许列表，到扩展管理页面复制实际的32字符 ID，再在配套目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -ExtensionId YOUR_32_CHARACTER_EXTENSION_ID
```

把示例中的 ID 替换成浏览器实际显示的 ID。此命令由你手动执行。

## 2. 在官方桌面应用登录

打开已安装的官方 DeepSeek Harness **0.2.0-rc.2**，在官方桌面应用中完成登录。BREVESS 通过官方 SDK 使用该保存登录。

Harness 的“检测到保存登录”仅说明官方客户端存在保存登录，**不代表当前账号、额度和模型已经通过实际请求验证**。后续仍需测试连接。

## 3. 在 BREVESS 创建连接

1. 打开设置 → **模型与连接**，点击 **新增**。
2. 给配置取名，Provider 选择 **本机 DeepSeek Harness**。
3. 点击 **刷新状态**。成功时可看到官方版本与保存登录状态。
4. 点击 **读取模型**，从官方目录选择模型。当前实测目录如下：

   | 模型 ID | 显示名称 | 输入能力 |
   | --- | --- | --- |
   | `deepseek-flash` | DeepSeek-V41-Flash | 文本、图片；读取原图的解图选此模型 |
   | `deepseek-v4-pro` | DeepSeek-V4-Pro | 文本；不能用于图片解图 |

5. 点击 **保存连接**，再点击 **测试连接**。测试会发送内置合成内容，执行实际模型请求。
6. 在 **按功能指定模型** 中，将需要的功能指定到这个 Profile。读取原图的解图须指定 `deepseek-flash`；纯图注分析和其他文本任务也可指定到另一个 Pro Profile。

需要 AI 分析论文时，在 **模型与连接** 勾选 **正文发送许可**。测试连接只发送内置合成内容，无需勾选这项许可。

推理开关关闭时，实际发送官方 `off`。开启后可选择自动、低、高、最高，以当前界面和官方目录为准；自动使用官方默认。任务单独设置会影响该任务的实际调用，不能仅凭 Profile 名称判断所用模型。

## 4. 常见提示

如果官方桌面已经登录并能运行，而插件的“刷新状态”和“读取模型”同时报“内容不完整或规则不安全：”（没有具体字段），请先更新 Windows 配套组件。R26.1 已将旧桥的这个错误改成明确的版本提示；只更新浏览器文件不能更新已注册的本机桥。完整解压本页列出的 R26 Windows 配套包后，运行其中的 `Install-Brevess-Codex-Bridge.cmd`，再重新加载扩展、刷新设置页。官方桌面的有效登录可以继续使用。

| 提示 | 操作 |
| --- | --- |
| 未找到官方 Harness | 确认官方应用已安装，并使用本轮新版 Windows 配套 |
| 未检测到保存登录 / 登录已失效 | 在官方桌面登录，再刷新状态和测试连接 |
| 本机桥不可用 | 检查配套安装是否成功、扩展 ID 是否匹配，重新加载扩展 |
| 版本不兼容 | 当前支持0.2.0-rc.2；新版官方 SDK 需对应适配的 BREVESS 配套 |
| Windows 配套组件版本过旧，不支持 Harness | 安装 R26 或更新版本的 Windows 配套组件，再重新加载扩展并刷新设置页 |
| 模型不可用 | 重新读取官方模型目录，选取当前账号提供的模型 |
| 所选模型不支持图片 | 解图切换到官方 `deepseek-flash` |
| 返回结构未通过校验 | 查看具体失败项。有效 Panel 可以保留；不能把失败的整图当作已完成 |

## 5. 怎样理解任务结果与 Token

完成通知应显示实际模型、耗时、输入/输出/总 Token；分批任务的统计应包含其实际模型调用。服务提供完整用量时使用实报值；取消、失败或缺少用量时可能显示**估算**。估算值与未知值不能当作精确消耗，未知也不等于零。请在本轮验收时检查通知的显示。

Harness 接口把 JSON Schema 放进提示词，BREVESS 再执行结构和来源校验；这**不是强制 JSON 解码**。模型仍可能返回非法 JSON、超长标题或科学事实错误。程序只进行有界修复，不能靠校验通过保证科学正确。

**本轮真实解图的结构校验已有通过结果，但科学内容验收仍失败。** Cell 测试论文的 Fig2 仍有 M/N 虚构统计配对与 E/F 时长遗漏；Fig6 存在条带及星号误读；Fig7 存在 P 值与比较组误配。具体见本轮验收清单。不要把“完成”或“结构通过”作为科学结论正确的保证。

## 6. 已测与待测

官方安装/模型目录、文本请求、图片请求和取消已进行真实测试；新版 Windows 可执行文件也完成了隔离 Native Messaging 测试。这些不替代更新后浏览器中的设置、任务路由和完成通知验收。

长文翻译相关单测已通过，最新版真实浏览器长文速度与完整性仍待测。Kokoro 实测中文58字首段约 **2.52秒**就绪，英文样本首段约 **1.65秒**；这是音频生成和解码的服务测试，**没有实测浏览器播放、听音或 IDM 兼容**。
