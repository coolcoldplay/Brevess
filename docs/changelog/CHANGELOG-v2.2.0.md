# 2.2.0：全文与 Figure 性能/质量优化

发布日期：2026-07-19  
运行修订：`2.2.0-performance-quality-r1`

## 主要变化

- 全文 LLM 高亮从串行分块改为最多 3 路有界并发；结果仍按原分块顺序合并。
- 并发任务的缓存检查点串行提交。某一分块失败时，其他已成功分块会保留，重试只补缺失项。
- 高亮、摘要、Figure 和跨 Figure 的自动输出预算整体提高；自动模式最多进行两次截断扩容，随后仍可由全文管线拆分过大的输入。
- 不同任务使用独立超时：高亮/摘要 180 秒，Figure/跨图逻辑 300 秒，避免复杂图解被统一的短超时提前终止。
- DeepSeek Chat Completions 改用非流式 JSON 响应，直接读取 `usage` 与 `finish_reason`；兼容仍错误返回 SSE 的网关。
- Provider 会回报脱敏遥测，包括耗时、输入/输出/推理 Token、缓存命中 Token 和完成原因，不包含 API Key 或响应正文。
- 多 Panel Figure 改为“并行 Panel 抽取 → 单次整图综合”。Panel 请求不再重复生成整图结论、逻辑桥和深度审计字段。
- 小 Figure 保留单次结构化请求快路径，减少额外往返。
- 批量和单图入口默认先生成标准解读；深度对照/因果审计按需触发。
- 文本型 Figure 路由（包括 DeepSeek 官方 API）在网页端直接跳过图片下载、Canvas 压缩和 Base64 编码，缓存键也不再依赖无用图片数据。
- 新增 Panel 综合阶段进度，缓存版本升级为 Figure v6。

## 兼容与边界

- 原有 Provider Profile、任务路由、API Key、本地档案与手动标注无需迁移。
- 标准和深度 Figure 继续分别缓存；Figure v6 会有意重新生成旧版图解缓存。
- 手动设置的固定输出 Token 不自动扩容；自动模式才使用动态预算。
- DeepSeek 官方模型仍按文本证据解图，不会声称读取了像素。若需像素级图像观察，请将 Figure 任务路由到明确支持视觉输入的 Provider/Profile。
