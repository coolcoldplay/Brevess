## 测试方法

- 使用安装了当前未打包扩展的真实 Microsoft Edge 持久化上下文。
- 每篇文章均从出版社 OA HTML 页面进入，不使用复制出的静态 HTML 代替真实页面。
- 对可访问页面同时核对：
  - 出版社原生标题与插件树标题；
  - 正文段落数量和正文根节点；
  - 主要章节视图与全部标题视图；
  - 点击章节后是否滚动到对应原生标题；
  - 截图中的面板层级、溢出、遮挡和聚焦反馈。
- 对安全验证页只验证“识别并停止”，不把验证页内容计为正文，也不声称该出版社已完成实时提取验证。

## 高亮分布真实交互测试

在 PLOS 正文的同一章节中放入：

- 1 条“结果陈述”手动荧光笔高亮；
- 1 条“局限性”手动荧光笔高亮。

分布视图生成 `章节 × 高亮类型` 矩阵，显示该章节两类计数均为 1；点击计数后准确滚动并聚焦对应高亮。

## 内存与重复打开测试

在同一 PLOS 页面连续打开并关闭论文导航 40 次，交替切换结构树与高亮分布，并在每 20 次后强制执行浏览器垃圾回收：

- JS Heap：约 32.1 MB → 33.3 MB → 33.9 MB；
- 40 次后的累计增量约 1.8 MB；
- 关闭后残留导航宿主节点：0；
- 正文段落标记：18 个，重复标记：0。

这不是对所有浏览器场景的形式化泄漏证明，但没有观察到随打开次数线性累积的面板 DOM、重复正文标记或失控内存增长。

## 本轮修复

- 出版社验证页检测与明确 UI 提示。
- PLOS 正文前导信息不再生成伪 `Article` 父节点。
- ACS 使用干净 `.article_content` 正文根；无分节文章跳转到首段。
- AAAS 作者资料与 collateral 面板按出版社专属选择器排除。
- bioRxiv 使用 `.highwire-markup` 正文根；目录覆盖不足时回退完整正文树。
- Outline 锚点直接绑定真实标题元素，避免滚动到超高章节容器。
- 统一结构与诊断清洗流程，避免诊断段落数和实际结构不一致。
- 图、表、推荐、作者、指标、AI 声明、脚注、参考文献等实用栏目进一步过滤。
