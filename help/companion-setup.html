Local connection · Windows · Brevess 1.0.1

Set up Local Codex

Connect Brevess to Codex App Server through Chromium Native Messaging for article questions and figure analysis.

The extension does not read or store plaintext sign-in tokens. Codex App Server keeps the extension’s authentication state in %LOCALAPPDATA%\BrevessCodexBridge\codex-home, separate from desktop Codex and the Codex CLI.

01 / Install on Windows

  1. Install Codex and confirm that this command works in PowerShell: 
    codex --version
  2. Open edge://extensions/ or chrome://extensions/ in your browser. Copy the current 32-character extension ID shown on the Brevess card.
  3. Open PowerShell in the extension build’s native-host folder. Replace YOUR_ACTUAL_EXTENSION_ID below with the ID you just copied, then run: 
    powershell -ExecutionPolicy Bypass -File .\install.ps1 -ExtensionId YOUR_ACTUAL_EXTENSION_ID
  4. Reload Brevess at edge://extensions/ or chrome://extensions/, then continue with sign-in below.

Use the ID displayed by your browser. The Edge store installation has a fixed store ID. Loading a store ZIP from a GitHub Release as an unpacked extension can produce another ID based on its folder path. Always pass the actual ID shown on the extension management page to install.ps1.

02 / Sign in and verify

  1. Open Brevess settings and create a profile. Choose Local Codex as its provider and use auto for the model.
  2. Under Extension-specific Codex session, select Sign in / Sign in again and complete authorization in the browser.
  3. When the status shows that you are signed in, save the profile and select Test connection. This runs one real, short model turn without saving a thread.
  4. In the model selector at the bottom of the article Q&A view, select this profile.

If the settings page cannot open sign-in

Run the fallback script from the same native-host folder:

powershell -ExecutionPolicy Bypass -File .\login.ps1

Do not substitute a normal codex login command. By default, that signs in to the CLI’s own CODEX_HOME, not the extension’s isolated directory.

03 / Data and permissions

  • Each paper and Codex profile pair is associated with a Codex thread. Thread mappings are stored in %LOCALAPPDATA%\BrevessCodexBridge\threads.json.
  • Codex manages the extension-specific sign-in state. Neither the extension nor the bridge exports sign-in tokens.
  • Desktop Codex, the Codex CLI and the extension do not share refresh tokens, preventing concurrent refreshes from invalidating one another’s sessions.
  • Codex threads start with a read-only sandbox and an approval policy that never requests approval. The prompt prohibits command, file, network, MCP and code-editing tools. The bridge also disables shell execution and web search.
  • The extension still divides article text according to its retrieval plan. Only the context needed for the current question is sent to Codex.

04 / Figure image input

Local Codex is registered as a vision model. Before figure analysis, the page extracts and compresses the original figure images, then sends them to the local bridge through Native Messaging.

The bridge creates temporary images for the current request only in %LOCALAPPDATA%\BrevessCodexBridge\turn-images and passes them to Codex App Server as localImage inputs. These images are deleted immediately after the model turn completes, fails or is canceled.

If cross-origin restrictions, a sign-in wall or a loading timeout prevents image access, Brevess explicitly falls back to captions and article text. It records visionFallback in the figure result and does not present a text-only result as visual analysis.

05 / Progress and results

When Local Codex generates Figure, Panel or cross-figure results, Brevess writes live progress and final results to a local event channel:

Latest state
%LOCALAPPDATA%\BrevessCodexBridge\reader-events\latest.json
Append-only event stream
%LOCALAPPDATA%\BrevessCodexBridge\reader-events\events.ndjson

The Local Codex status area in settings shows the actual paths. Events contain page identity, task progress and model results; they do not contain API keys, sign-in tokens or Base64 image data. At 16 MB, the event log rotates to events.previous.ndjson.

Desktop Codex can read these files when needed, without depending on whether the browser sidebar’s DOM permits automation.

06 / Sign out or uninstall

To end only the extension-specific session, use Sign out of extension session in the Local Codex session controls. Desktop and command-line Codex sessions are unaffected.

To remove the bridge registration from both Edge and Chrome, run the uninstall script from the extension build’s native-host folder:

powershell -ExecutionPolicy Bypass -File .\uninstall.ps1

The script does not automatically delete %LOCALAPPDATA%\BrevessCodexBridge, so the thread mappings remain recoverable.
